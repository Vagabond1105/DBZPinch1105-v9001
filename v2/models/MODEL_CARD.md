## What they are

- **(a) Run classifier**: input = the 64 features of a *finished* run (zpinch/analysis/features.py); output = probability of each outcome class.
- **(b) Outcome predictor**: input = only what is known *before* pressing Start (the 8 swept settings and the stability numbers computed from them, e.g. n q); output = probability of each outcome.
- Both: gradient-boosted trees (`HistGradientBoostingClassifier`), labels = the physics rules (zpinch/analysis/rules.py).

## Limits

- The labels come from rules, not from experiments. (a) mostly learns the rules back; its use is the probabilities and the disagreements.
- (b) is only meaningful inside the swept box (tools/sweep.py) at 32^3 with the default seed perturbation, pinch radius and background density. The GUI warns outside it.
- Thin classes (radiative collapse, resistive diffusion) have few test runs, so their per-class numbers are uncertain by ±10-20 %.
- The random seed of a run is not an input, so runs with the same settings but different seeds can differ; this caps (b)'s possible accuracy.
