# 05.4 · V3 Phase 5: the run report, in the GUI and as a file

> [!abstract] One-sentence version
> Run the simulation and it **pauses itself at t = 3 and opens a report panel** beside the 3D view. The panel shows the hand-written explanation, three figures and the data behind them. One button saves the same report as a **single HTML page** that opens in any browser, and another loads the **textbook run** the explanation was checked on.

## 1. What Phase 5 is for

Phases 1–4 made the analysis: what happened, why, what to try next, and the numbers behind it. But you could only read it as plain text in a pop-up box or a terminal. The plan's "done" test for Phase 5 is:

> *A student can run, finish and read the report without help.*

So Phase 5 adds no new physics. It puts what is already there **where a student will see it, in the order a student needs it**.

---

## 2. What you see now

### In the window

| Where | What's new |
|---|---|
| **Run** box | **Textbook run**: a list of the 12 sweep runs the library entries were checked on. Pick one and its exact settings load. |
| **Run** box | **Pause & analyse at t = 3** (on by default). The run stops by itself at t = 3 and the report opens. *Resume* carries on past it. |
| **Run report** panel (right side, opens on the first report) | The write-up first (*What happened*, *Why*, *Try next*), then three figures, then the data appendix. You can drag it out to its own window or close it. |
| Panel buttons | **Save report...** (HTML or plain text) · **Copy as text** · **Load its textbook run** · **Load preset: ...** (when the entry names one) |

**Why stop at t = 3?** The overnight sweep ran every case to t = 3, and the outcome predictor forecasts the outcome at t = 3. Analysing at the same moment means your run, the textbook run and the "Predicted outcome" line are all compared like with like. Before this, a run carried on until you stopped it, and a report at t = 1.2 can't be compared with anything.

### The three figures

1. **Instability amplitudes.** The kink (m = 1, how far the column's centre line wanders) and the sausage (m = 0, how much its radius varies), both relative to the column's mean radius, on a log scale. Each phase of the timeline (*Kink growth*, *Saturated helical kink*, ...) is a shaded band, so you can see *when* the program thinks each thing happened.
2. **Energy.** The kinetic, magnetic, thermal and total energy. A dotted red line shows what the total *should* be from the circuit, radiation and floor corrections. The black line sitting on the red one is the visual proof that the bookkeeping closes.
3. **The column.** Its radius and the core temperature and density, relative to the start.

### The standalone HTML report

The **Save report...** button writes one `.html` file, and the export zip now includes it too (`report.html`, next to `analysis.txt`, `analysis.json`, the new `features.csv` and the time series). The figures are embedded inside the file, nothing is fetched from the internet, and it follows your browser's light or dark theme. It's meant for showing someone a run without launching the program: email it, or open it in a demo.

Long sections of the data appendix (the parameters, all 65 features) are folded away in the HTML. Click to open them.

## 3. How it works

| File | What it does |
|---|---|
| `v2/zpinch/analysis/report.py` | **New.** Builds the report as HTML from the analysis result: `figures()` draws the three PNGs, `body()` writes the content, `html()` wraps it into a standalone page, `bundle()` does all of it in one call. |
| `v2/zpinch/gui/worker.py` | The physics process now builds the whole report bundle (so the window never freezes while it's drawn). It also takes a new `stop_at` message: pause once when the time first passes t. |
| `v2/zpinch/gui/app.py` | The report panel (`ReportView`, a Qt text browser that serves the figures from memory), the textbook-run list, the pause-at control, and the buttons. |
| `v2/zpinch/diagnostics.py` | The export zip gains `report.html` and `features.csv`. |
| `v2/zpinch/analysis/writeup.py` | `load_examples()`: the textbook runs, with each entry's title. |
| `v2/tools/library.py` | `show --html` (any sweep run's full report) and `replay` (see §4). |
| `v2/main.py` | `--report run.html` for headless runs. |

**One builder, two readers.** Qt's text widget understands only a subset of HTML: no stylesheet variables, no fold-away sections, no embedded images. So `body()` takes a `standalone` switch. The browser version gets folding sections, a light/dark stylesheet and embedded images. The panel version gets plain headings and images the panel serves from memory. The words are identical, so the panel and the saved file can't drift apart.

### A stale number this found

Putting the write-up and the criteria table on the same page showed them **disagreeing**: the write-up said "70 of the 70 runs in this band saturated" and the criteria table said "sweep: 43 of 43 saturated". Both were true once. The 43 was typed into `explain.py` in Phase 1, from the first part of the sweep. The 70 is counted by `tools/library.py stats` from the current labels.

The fix: `library.py stats` now also counts the four Kruskal–Shafranov bands (n q below 0.5, 0.5–1, 1–1.5, above 1.5), using the same "little gravity or cooling" cut as the library. The criteria table reads them from `stats.json`. Every sweep number in a report now comes from one file and is recounted in one step.

## 4. Does a textbook run reproduce?

A textbook run is only worth a button if pressing it gives the same outcome. That isn't automatic. The sweep ran each case on **one** CPU thread; the GUI runs on several. More threads change the order in which the parallel loops add numbers up, so the last digits differ. A kink grows exponentially from noise, so a last-digit difference could in principle grow too.

So `tools/library.py replay` re-simulates every textbook run from `examples.json` alone, multi-threaded and with tracers, exactly as the GUI does. It fails if any lands in a different class.

*Not run yet: it needs the CPU the overnight sweep is using. It runs with the retrain, after the sweep stops, and the result goes here.*

- **The whole loop, in the real window** (offscreen, driven by a script): pick the textbook run *Saturated kink just inside the Kruskal–Shafranov limit*, press Start, wait. The settings loaded exactly (B_z = 0.6174, tracers kept on), the run **paused itself** at the set time, the report panel opened, and the buttons switched on and off correctly. ## 6. How to use it

In the GUI: pick a **Textbook run** (or a preset, or your own settings), press **Start**, and wait for t = 3. The report opens by itself. Read it top to bottom; the buttons at the top of the panel save it or load the textbook run it was checked on.

From `v2/`:

```bash
./run.sh --headless --t-end 3 --preset "Stable screw pinch" --report stable.html
.venv/bin/python tools/library.py show dataset/sweep-2026-10-19/runs/r00273.npz --html r00273.html
.venv/bin/python tools/library.py replay                        # every textbook run, re-simulated
```

---

## 7. Honest limits

- **The panel is Qt's text widget**, so it looks plainer than the saved HTML (no folding sections, simpler tables). The words are the same.
- **The figures are drawn at the moment of analysis.** Resume and analyse again for a newer report; the panel always shows the latest.
- **"Pause at t = 3" pauses once.** If you resume, it doesn't stop again unless you move the pause time past the current time.
- **A textbook run takes as long as any run**: a few minutes at the default grid, depending on the machine.
